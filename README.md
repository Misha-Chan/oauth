# oauth (وسيط تحقق مركزي)

نطاق مستقل (`oauth.hostaka.fun`) — خدمة صغيرة جداً، مهمتها الوحيدة إنها
تحل مشكلة تسجيل الدخول عبر النطاقات الفرعية (hostaka.fun، orbithub،
aethercast، console...).

## المشكلة اللي يحلّها

`localStorage` مو مشترك بين النطاقات الفرعية — كل واحد منها (hostaka.fun،
orbithub.hostaka.fun...) يشوف نسخة منفصلة تماماً. قبل هذا المستودع، كل
نطاق فرعي كان يعتمد على تمرير التوكن يدوياً برابط `?token=` عند كل
انتقال من الموقع الرئيسي. المشكلة الحقيقية كانت: لو المستخدم يفتح نطاق
فرعي مباشرة (مو عبر رابط فيه توكن) ويحاول يسجّل دخول، صفحة تسجيل الدخول
بالموقع الرئيسي تكتشف إنه مسجّل دخول أصلاً هناك وتوديه للصفحة الرئيسية
مباشرة — بدون رجوع للنطاق الفرعي اللي طلب الدخول أصلاً.

## الحل

كوكي واحد مشترك، مضبوط على `Domain=.hostaka.fun` (لاحظ النقطة بالبداية)
— أي كوكي بهذا الشكل يوصل تلقائياً لأي طلب لأي نطاق فرعي تحت
`hostaka.fun`، بغض النظر مين النطاق اللي أنشأه أصلاً. هذا السيرفر بس
"صندوق بريد" آمن يخزّن/يقرأ/يمسح هذا الكوكي — **ما له علاقة بمنطق تسجيل
الدخول نفسه** (بريد/كلمة مرور/2FA...)، كله لسا بالكامل على hostaka.fun.

## الـ API

| المسار | الطريقة | الوصف |
|---|---|---|
| `/api/token` | `POST` | يخزّن توكن جديد بالكوكي المشترك. يُستدعى من hostaka.fun فور نجاح تسجيل الدخول. Body: `{ "token": "..." }` |
| `/api/token` | `GET` | يرجّع التوكن المخزّن (لو موجود). يُستدعى من أي نطاق فرعي عند تحميل الصفحة، بدون توكن محلي. |
| `/api/token` | `DELETE` | يمسح الكوكي المشترك (تسجيل خروج). |

كل الطلبات تحتاج `credentials: 'include'` من طرف المتصفح عشان الكوكي
يترسل/يُقرأ عبر النطاقات. الـ CORS مضبوط يدوياً بحيث يعكس الـ Origin
الحقيقي (لا `*`) لأي طلب من نطاق فرعي حقيقي تحت `hostaka.fun` فقط —
أي نطاق ثاني يترفض بصمت (بدون هيدر CORS، فالمتصفح يمنع قراءة الرد).

## التدفق الكامل

1. المستخدم يسجّل دخول بنجاح على `hostaka.fun` → `login.js` يستدعي
   `POST oauth.hostaka.fun/api/token` (صامت، fire-and-forget) → يتخزّن
   الكوكي المشترك.
2. المستخدم يفتح أي نطاق فرعي (orbithub/aethercast/console) بدون توكن
   محلي → الصفحة تستدعي `GET oauth.hostaka.fun/api/token` (بصمت، قبل ما
   تعرض أي حالة "غير مسجّل دخول") → لو رجع توكن، يتخزّن محلياً بهذا
   النطاق تلقائياً، والمستخدم يبان مسجّل دخول من غير ما يعمل أي شي.
3. لو حتى ذا فشل (أول مرة يزور فيها أي نطاق تابع لهوستاكا إطلاقاً)،
   يرجع لنفس آلية `?token=` القديمة (لسا موجودة كـ fallback) — يضغط
   "تسجيل دخول"، يروح `hostaka.fun/login?next=<رابط الرجوع>`، وبعد
   الدخول يرجع تلقائياً لمكانه (تم إصلاح هذا بـ `login.js` بالمشروع
   الرئيسي — كان فيه Bug يتجاهل `?next=` تماماً).
4. تسجيل الخروج من hostaka.fun يمسح الكوكي المشترك كمان (`DELETE`)، عشان
   نطاق فرعي ثاني ما يلتقط جلسة قديمة بالغلط.

## اختبار محلي

```bash
npm install
npm start
```

## النشر على Vercel

1. مشروع Vercel جديد من هذا المستودع.
2. أضف دومين `oauth.hostaka.fun` من Settings → Domains.
3. أضف سجل `CNAME` باسم `oauth` بـ DNS حق `hostaka.fun`.

## متغيرات البيئة

| المتغير | مطلوب؟ | الوصف |
|---|---|---|
| `VERIFY_TOKENS` | ❌ اختياري (افتراضياً `0`) | فعّله بـ `1` للتحقق من توقيع JWT قبل قبول أي توكن. **لازم** يطابقه `JWT_SECRET` القيمة الحقيقية بمشروع hostaka-main بالضبط، وإلا كل توكن حقيقي بينرفض وينكسر التدفق كامل بصمت. اتركه معطّل لحد ما تتأكد إن التدفق الأساسي شغّال. |
| `JWT_SECRET` | ❌ فقط لو `VERIFY_TOKENS=1` | نفس القيمة المضبوطة بمشروع hostaka-main. |
| `COOKIE_DOMAIN` | ❌ اختياري (افتراضياً `.hostaka.fun`) | نطاق الكوكي المشترك. |

## ⚠️ خطوات لازم تسويها بباقي المشاريع

هذا المستودع لحاله ما يسوي شي — لازم:

1. **hostaka-main:** `login.js` محدَّث أصلاً (بهذه الجولة) يستدعي
   `oauth.hostaka.fun/api/token` تلقائياً بعد كل تسجيل دخول ناجح، ويمسحه
   عند الخروج (`index.js`). تأكد تنشر النسخة المحدّثة.
2. **orbithub / aethercast / console:** الملفات الرئيسية (`chat.js`,
   `group.js`, `video.js`, `short.js`, `console.js`, `index-landing.js`)
   محدَّثة أصلاً تسحب الجلسة بصمت من oauth عند التحميل لو ما فيه توكن
   محلي. تأكد تنشر النسخ المحدّثة من الثلاثة.
3. **مهم:** لأن الكوكي `SameSite=Lax` ومضبوط `Domain=.hostaka.fun`،
   لازم كل النطاقات الفرعية تكون فعلاً subdomains حقيقية لنفس
   `hostaka.fun` (مو نطاقات منفصلة تماماً) عشان يشتغل التدفق.
